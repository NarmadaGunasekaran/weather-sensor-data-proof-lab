The challenge

How do we make weather data smaller without losing anything?

Our app receives one day of temperature, humidity, wind and rainfall data as a JSON file. We want it to cost less to send and store.

Weather data
1,177 bytes

Smaller file
Every original value must come back exactly.
Lossless means: after decoding, every original character, number, and measurement is identical.
01

Train the compression agent.

The program studies seven earlier weather files. It learns small repeating patterns—such as timestamps, JSON labels, commas, and common number formats.

Fixed weather agent
Think of it as making a short prediction guide before new data arrives.
02

Compress new weather data.

For each character, the trained agent makes a prediction. Instead of storing the full character again, the system stores the tiny difference between its prediction and the real character.

Agent predicts
“t”
+
Exact difference
The difference is always kept, so nothing is guessed or discarded.
If the prediction is wrong, the saved difference still contains everything needed to fix it.
03

Reconstruct exactly.

The receiver has the same fixed agent. It makes the same prediction, adds the saved difference, and gets the original character back—one by one.

A fingerprint checks that the correct trained agent is used.
This is deterministic: the same inputs always recreate the same original weather file.
The result

Compare it fairly.

We run the trained agent beside established methods such as zlib, gzip, bz2 and lzma. Every method is tested by decoding its output and comparing its SHA-256 checksum.

The trained agent wins this demo by 9 bytes. Real deployment needs a larger, representative dataset.
The honest conclusion: the approach is promising for structured sensor data, but every real use case needs its own benchmark.
